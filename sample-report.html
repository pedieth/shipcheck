An example of the report you get, written for a fictional notes app on Supabase. The findings are illustrative, picked from the mistakes that most often show up in fast-built apps. No real app, users or client data are involved.

StackReact + Supabase (Postgres, Auth, Storage)
ScopePublic site, Supabase REST API, Storage, Auth settings
MethodFrom the outside, with the public anon key and test accounts
Result1 critical1 high1 medium1 low

Findings

Critical Any visitor can read every user's notes

What: Row level security is off on the notes table. The anon key in the site's JavaScript is enough to read all rows.

GET /rest/v1/notes?select=*
apikey: <public anon key>
→ 200, returns notes from every account

Fix: turn RLS on and allow each user only their own rows.

alter table notes enable row level security;

create policy "own notes" on notes
  for all using (auth.uid() = user_id)
  with check (auth.uid() = user_id);

High Attachments bucket is public and listable

What: The attachments bucket is marked public, so anyone who guesses or lists a path can download files from other users.

Fix: make the bucket private, store files under the user's id, and serve them with signed URLs.

create policy "own files" on storage.objects
  for select using (
    bucket_id = 'attachments'
    and (storage.foldername(name))[1] = auth.uid()::text
  );

Medium Profile update trusts the user id from the client

What: The update_profile function takes a user_id argument, so a signed-in user can change someone else's display name.

Fix: drop the argument and use auth.uid() inside the function.

Low Email confirmation is off

What: Accounts work without confirming the email, which makes fake sign-ups and spam easy.

Fix: Authentication → Providers → Email → turn on "Confirm email".

Passed

  • No service role key in the shipped JavaScript
  • Auth redirect URLs limited to the app's own domain
  • No edge functions callable without a session
